# astrbot_plugin_link_reader

让模型能读到群友发的**网页链接正文**，而不是只看到一串 URL。

## 解决什么问题

群聊里分享链接时，模型原本只能看到 URL，打不开也读不了。实测它会去试
`astrbot_execute_shell`（仅管理员可用，被拒），失败后编一个理由，比如
「这个接口可能要登录」——比说不出更糟。

## 做了什么

- 以高优先级消息处理器运行：从消息里提取前两个链接，抓取后把标题和正文追加到
  `event.message_str`，让模型在生成回复前就能读到内容
- 失败时给出**具体原因**（HTTP 403、content-type 不是网页、网络失败、空响应等），
  让模型如实转述，而不是自己猜一个

## 安全

链接由群友控制，所以：

- 抓取前解析主机，拒绝回环、私有、链路本地、保留和组播地址
- 重定向的每一跳都重新检查
- 响应同时限制时间和体积

残余风险：DNS rebinding 仍可能让连接落到私网地址。群聊场景可接受，要收紧得在连接层做校验。

## 边界

- 会跳过 `astrbot_plugin_multi_parser` 已支持的平台域名，交给那个插件走平台接口；
  GitHub 例外——`multi_parser` 只渲染卡片图，抓页面能让模型真的读到 README
- 只覆盖静态页面和 JSON 接口。需要 JavaScript 渲染的单页应用取不到正文，
  此时会明确告诉模型「页面没有可直接读取的正文」

## 安装

把本仓库放进 AstrBot 的 `data/plugins/` 目录，重启 AstrBot，然后
`pip install -r requirements.txt`（若框架未自动安装）。

## 兼容性

- 平台：`aiocqhttp`
- AstrBot：`>=4.16,<5`
